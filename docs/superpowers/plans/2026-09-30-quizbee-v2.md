# QuizBee 2.0 Implementation Plan

> Historical rebuild plan. Source paths below reflect the October 1 service extraction; current runtime and verification guidance is in `docs/ARCHITECTURE.md` and `docs/TESTING.md`.
> **For agentic workers:** Use superpowers:subagent-driven-development or superpowers:executing-plans. Track completed slices and actual test evidence here.

**Goal:** Deliver locally runnable, persistent QuizBee study and assessment workflows while retaining legacy behavior.

**Architecture:** Next.js same-origin API delegates to strict domain/services backed by a separate PostgreSQL database. A worker performs ingestion and provider generation. Legacy Express/MongoDB stays intact.

**Tech Stack:** Next.js 15, React, TypeScript, Tailwind, Radix/shadcn, Lucide, Prisma 6, PostgreSQL, Node test runner and Playwright.

**Spec:** `docs/superpowers/specs/2026-09-30-quizbee-v2-design.md`

## Global constraints

- Local testing only; no deployment, production data migration or destructive legacy edits.
- Server-authoritative grades/timing, immutable versions, private ownership and validated input/output.
- No fake activity or AI; unconfigured integrations have explicit errors.
- Run legacy and new tests, strict type checking and production build.

## Review focus

- A refreshed or concurrently submitted attempt preserves the same deadline, snapshot and final result.
- Another user's IDs never grant access to materials, quizzes, courses, attempts or results.
- A malformed later question, generated answer or ZIP entry fails the entire operation.
- Expired attempts reject answer changes and cannot gain extra time through refresh.
- Provider/configuration failures are recoverable and never displayed as successful generation.
